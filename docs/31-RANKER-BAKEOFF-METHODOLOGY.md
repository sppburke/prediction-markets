# 31 — Ranker Bake-off Methodology

> See `_BASELINE.md` for the toolchain pin, lints, and common acceptance gate.
> See `_GLOSSARY.md` for vocabulary (wallet/trader/leader/candidate), type aliases, and **all** ranker configuration defaults — this doc references those keys by name rather than restating values.
> See `16-RUST-WORKSPACE-ARCHITECTURE.md` for the `pe-backtest` seam and `26-DATA-REFRESH-AND-REOPTIMIZATION-RUNBOOK.md` for the production ranking refresh this harness evaluates.

**This file is the canonical description of the modular ranker evaluation harness (issue #421) — the swappable-module bake-off that decides which wallets the copy-trader should follow.** It documents *what is implemented* in `scripts/ranker/` at the close of the #421 PR sequence (PR1–PR5), the honesty guards that keep its verdict trustworthy, and the boundary between the live menu and the reserved seams. The harness produces a **grid-deflated leaderboard → a recommended winning config (or an explicit NO-GO)** that feeds productionization in #417. It deploys nothing on its own: the bake-off **run** is a separate operator compute step (§Running the bake-off), and a NO-GO is a valid deliverable.

## Why the redesign

The previous ranker selected on raw net t-stat ≥ 2.0 plus a greedy max-group-Sharpe portfolio step. Per the issue #421 forensics this is a textbook **winner's-curse** failure: the top-ranked wallets bled in live paper trading, the #8-ranked wallet was the single worst live performer, and ~82% of realized P&L traced to one wallet. Ranking on an unshrunk, un-deflated point estimate selects the luckiest sample, not the most skilled wallet. The redesign keeps trading mechanics and buy-and-hold-to-resolution execution **fixed** and changes only the *ranking math*, behind a permanent modular harness so every estimator, selector, criterion, and transition policy is a swappable module measured on our own data.

The target question every experiment must answer is narrow and operational: **"which wallets should we follow right now?"** — enforced by forward walk-forward scoring, the `resolved_at ≤ as_of` look-ahead guard, and an activity-recency eligibility gate (a dormant wallet is not a follow-now candidate).

## Unit of evaluation: the set-transition policy

The deployed system does not pick a point-in-time snapshot — it **maintains a followed set over time** (currently incremental knockout + backfill in `crates/service/src/watchlist_maintenance.rs`). A ranking that looks excellent at a single cutoff but behaves badly under the real maintenance policy is a false positive. So the bake-off's unit of evaluation is the **set-transition policy**: each candidate config is run as a walk-forward *trajectory* —

```
set_t  →  pe-backtest(set_t)  →  live_pnl_t  →  policy.step(...)  →  set_{t+1}
```

— and scored by **cumulative forward copy P&L over the trajectory, net of churn cost** — realized closes **plus** the CLOB forward mark-to-market of still-open positions at each window's horizon (issue #436 Phase E, §Forward mark-to-market). The four policies are a first-class axis (§The modular menu).

## The shared substrate — `suff_stats`

Every module reads one materialized frame, `scripts/ranker/suff_stats.py`, so no module can drift from the production position definition: `materialize` calls `ranker_duck.duck_extract_positions` (the same first-buy join the live ranker uses) over a permissive superset, and the criteria slice happens downstream in pandas. One row per qualifying first-buy position, thirteen columns: `wallet`, `market`, `outcome_id`, `entry_ts`, `ttr_ref` (absolute per-market scheduled close), `resolved_at`, `price`, `payoff`, `dollar_size`, `_eff` (slip-adjusted effective entry), `c_t` (entry-instant concurrency), `close_proxy` (last pre-resolution trade price on the bought outcome — added in PR5 for the CLV estimator; `NaN` when the outcome never traded pre-resolution), and `true_clv_close` (CLOB mid at/just-before market close on the bought outcome — issue #429 PR4; `NaN` when no CLOB series covers it or the optional CLOB views are absent).

`close_proxy` is derived in SQL (`arg_max(price, timestamp)` over `trades` strictly before `resolved_at`) and left-joined on; the `proxy_clv` estimator reads it as a column and never touches the database. The slip default and effective-entry cap mirror `rank_72hr_buyandhold.py`.

`true_clv_close` (issue #429 PR4) is the same shape but sourced from the CLOB price series instead of the trade tape: `arg_max(price, t)` over `market_price_history` (`source='clob'`) where `t ≤ LEAST(COALESCE(end_date_unix, resolved_at_unix), resolved_at_unix)` — the scheduled close, **capped at resolution** — with the bought `outcome_id` mapped to a CLOB `token_id` via `token_conditions.outcome_index` (rows with NULL `outcome_index` skipped). It pins to the market **close**, intentionally distinct from `proxy_clv`'s last pre-resolution **trade** price, so `true_clv = close − entry` re-ranks vs `proxy_clv` (PR2 measured a wallet-rank Spearman of only 0.21). The `LEAST(…, resolved_at)` cap is the **issue #436 B5** leak fix: the original plain `COALESCE(end_date_unix, resolved_at_unix)` anchor pinned the close to a tick dated after resolution for an **early-resolved** market (`resolved_at < end_date`) — and after `as_of` for any in-sample position (`resolved_at ≤ as_of` by the look-ahead split below), a look-ahead the once-materialized window-agnostic column could not clamp per-`as_of`. Capping at `resolved_at` closes it for all in-sample positions, is a sounder CLV anchor (post-resolution ticks are 0/1 echoes of the known payoff, not a consensus line), and changes **only** early-resolved markets (the normal `resolved_at ≥ end_date` case still pins to `end_date`). `market_price_history` + `token_conditions` are OPTIONAL views (registered only after the prices-history backfill + export); absent them, `true_clv_close` is all-`NaN`. Rather than letting that all-`NaN` arm flow silently into the grid and be "eliminated downstream", the **#445 defect-10 preflight** (`true_clv_preflight`, run in `main` before `N_GRID` is frozen) **excludes `true_clv` from the estimator axis** when the CLOB views are absent OR position-level `true_clv_close` coverage is below `true_clv_coverage_warn_pct` (canonical default in `_GLOSSARY.md`; no second threshold is introduced). The exclusion is a hard flag in `true_clv_preflight.json` + the decision payload — never a silent all-NaN ranking — and aborts loudly if it leaves no estimator; the non-CLV axes run unaffected. Coverage is also logged in `materialize` (the warn-only log under `true_clv_coverage_warn_pct` remains).

## The modular menu

Each axis is a `typing.Protocol` in `scripts/ranker/__init__.py`; every concrete module sets a class-level `name` string and is registered in its module's `*_REGISTRY` keyed by `.name`. The bake-off composes a config by naming one module per axis. **Implemented in v1** vs **reserved seams** (Protocol declared, no v1 concrete — deliberate extension points, not active axes):

| Axis | Protocol | Implemented in v1 (`.name`) | Reserved seams |
|---|---|---|---|
| **Estimator** (per-wallet skill) | `Estimator.score` | `eb_shrinkage_skill`, `t_stat_baseline` (the winner's-curse baseline every challenger must beat), `gu_koenker_npmle`, `proxy_clv`, `true_clv` (CLOB close-pinned CLV — #429 PR4) | r-value, Brier/CRPS, and the rest of the §menu drop-ins |
| **Signal combiner** | `SignalCombiner.combine` | *(none — single-signal in v1)* | multi-signal blends |
| **Deflation / calibration** | `Deflator.deflate` | `deflated_sharpe` (the deflation axis also accepts the literal `"none"` passthrough sentinel — a bypass recognised by the driver, not a `*_REGISTRY` class) | — |
| **Selector** | `Selector.select` | `top_k`, `online_exp_weights` | corr-aware, weighted-conformal, TTTS-online, full BOA |
| **Set-transition policy** | `SetTransitionPolicy.step` | `policy_full_rerank` (baseline), `policy_knockout_backfill` (the current live behaviour), `policy_hybrid_displacement`, `policy_online_weighting` | — |
| **Integrity filter** | `IntegrityFilter.mask` | *(none)* — overlap is handled continuously by the uniqueness weights (§Honesty), not a threshold | overlap-ratio / wash / coordination filters |
| **Capacity filter** | `CapacityFilter.haircut` | *(none)* | liquidity-at-fill haircut |
| **Demotion** | `Demoter.should_demote` | `empirical_bernstein` (demote iff the empirical-Bernstein upper CB on per-period P&L < 0 **and** cumulative realized P&L < 0) | `wallet_skill_cpd` change-point |
| **Criteria** (frozen dataclass, swept in the grid) | `Criteria` | `active_within_secs`, `ttr_hours`, `price_min`/`price_max` (entry band), `half_life_days` (recency decay), `min_trl` (minimum track-record length) | — |

The estimators all compute per-position net edge `(payoff − _eff) / _eff` and reuse `ranker_decay.weighted_stats`, so the AFML uniqueness weights apply uniformly — but the bake-off passes *only* the uniqueness weights: the `Criteria.half_life_days` recency-decay field is **carried but not consumed** in v1 (no estimator or filter reads it; it only labels the config key), so Phase D holds it constant rather than sweeping it (sweeping an inert field would merely duplicate grid columns under distinct keys). Wiring #366 recency decay into estimator scoring is a deferred extension (→ #417/#418). A wallet with near-zero per-position dispersion (`sd ≤ ranker_sd_floor`) has an undefined t-stat / posterior and is **dropped** from every estimator's ranking, not scored maximal: the floor (`1e-9`) separates float noise (`np.std(ddof=1)` of a mathematically-constant net series is `0.0` at some position counts but `~1e-16` at others) from a genuine `O(1e-3)` dispersion, so a constant win-streak can't masquerade as a `~2e16` t-stat (issue #436 A10 follow-up; extends the deliberate `t_stat_baseline` zero-dispersion drop uniformly to all five estimators). `eb_shrinkage_skill` is **empirical** Bayes: the normal-normal prior mean μ0 and variance τ² are estimated from the cross-section at every scoring step. τ² uses the **DerSimonian-Laird precision-weighted (`1/se²`) positive-part** moment estimator over the finite-precision wallets (issue #436 C1) — the old unweighted `Var(means) − mean(se²)` let a handful of short-track (`n ≤ 4`, huge `se²`) wallets drive τ² negative, collapsing every posterior onto the prior mean and flattening the ranking into insertion order; precision-weighting denies the noisy wallets that leverage, and τ² is floored to a small fraction of `Var(means)` (`ranker_eb_tau2_floor_frac`) so a genuine-zero τ² still leaves a usable ranking, with `ranker_eb_prior_var_floor` the absolute `<2`-candidate fallback. **The prior mean μ0 includes EVERY candidate's mean (#445 defect 8)** — including the zero-dispersion wallets dropped from scoring — because μ0 is a cross-sectional *location* estimate well-defined for any candidate, whereas τ² and the posterior need a finite sampling variance and so restrict to the finite-SE subset; this asymmetry is retained and locked by a sensitivity test (changing μ0 membership later is a deliberate modeling decision). `gu_koenker_npmle` fits its NPMLE prior by EM in **log space** (log-sum-exp) and scores in log space too, so a far-from-grid precise wallet is not underflowed to score `0.0`; its `θ = 0` grid boundary splits mass 0.5/0.5 for a deterministic `[θ > 0]`, and the EM iteration cap is a safety ceiling the verdict is invariant to (issue #436 C2). (This is why the EB prior here is named distinctly from the *fixed* Kelly sizing priors `kelly_p_prior_*` in `19-WINNER-FOLLOW-STRATEGY.md`: those are fixed Beta(α,β) parameters; the EB ranker prior is data-derived.)

The selector axis is **coupled into the policy** in v1 (`policy_online_weighting` *is* the `online_exp_weights` selector carried across steps), so the swept grid is `estimator × deflator × policy × criteria × churn_cost`.

**The criteria sweep (issue #436 D1).** `build_criteria_grid` (`bakeoff.py`) materializes the criteria axis as the cartesian product of three swept levels — **TTR ∈ {72, 24, 48} h × entry band ∈ {0.15–0.85, 0.30–0.70} × MinTRL ∈ {0, 20} = 12 levels** — with `active_within_secs` and `half_life_days` held constant (the latter is inert in v1, above). These are *research-grid* levels, not fixed defaults: the winning level feeds #417, so they live here and in the code, not as single `_GLOSSARY` values (the one glossary'd swept knob is `ranker_min_trl`). Each level list is ordered **operator-default-first** (72 h, the wide 0.15–0.85 band, no MinTRL gate), and `itertools.product` varies the last axis fastest, so `criteria[0]` is the operator-default by construction. **A3↔D1 resolution:** the 8a estimator screen runs under a single **canonical criteria = `criteria[0]`** (the operator-default level) — *not* per-criteria — so the screen's universe stays well-defined as the trajectory axis goes plural; `criteria[0]` is also the baseline config's criteria. The operator narrows the sweep with `--ttr-hours` / `--bands` (as `lo:hi`) / `--min-trl` to bound compute.

## The honesty layer

The harness's value is entirely in its guards; `scripts/ranker/oos_validation.py` and `scripts/ranker/deflation.py` hold them. Per `oos_validation.py`'s own header, the numerics inside the validators are *statistical-method parameters* (bootstrap reps, RNG seeds, CSCV group counts) or honest sentinels — not strategy thresholds — so they stay as code constants; only the strategy-level levels are glossary'd (§Configuration defaults).

- **AFML uniqueness weights** (`uniqueness_weights`, López de Prado AFML Ch.4) — the true time-averaged uniqueness `ū_i = (1/|span_i|) ∫ (1/c_t) dt`, where `c_t` is the count of *that wallet's* labels live at `t`. A wallet whose positions heavily overlap is down-weighted continuously; this is how "overlap ratio" is handled — a weight, not a cutoff. Weights normalize to mean 1 per wallet, concatenated across wallets. **It is a *relative* (mean-1) weight, not an absolute sample-size penalty (#445 defect 6):** because the weights normalize to mean 1 and `weighted_stats` is scale-invariant, a frame in which *every* wallet overlaps identically yields all-equal weights and therefore the same `n_eff`/t-stat as the unweighted statistic — uniform overlap is **not** penalized; uniqueness bites only on *differential* average uniqueness within the same scoring frame. Turning this into an absolute overlap penalty would be a deliberate future change (locked by a regression/sensitivity test). Relatedly, `weighted_stats` applies its `W ≤ 0` (sum-of-weights) NaN guard **before** the uniform-weight short-circuit (#445), so an all-zero weight vector returns NaN rather than a spurious unweighted statistic.
- **Look-ahead guard** (LANDMINE-2; `split_walkforward` + `assert_no_lookahead`) — at cutoff `as_of`, in-sample = labels entered before `as_of` **and** already `resolved_at ≤ as_of`; forward = labels entered in `[as_of + embargo, as_of + horizon)`. The embargo (`ranker_embargo_secs`, default 0) shifts the forward start forward to break leakage across the cutoff. It is a per-`as_of` row filter over the once-materialized frame, not a per-cutoff rebuild of the join. `split_walkforward` **arms** `assert_no_lookahead` on its in-sample output on the hot path (issue #436 B1), not just in tests, so any future refactor that reintroduced a post-`as_of` in-sample row fails loudly there rather than as a silent leak. Forward windows additionally must not **overlap** across cutoffs: `BakeoffParams` rejects consecutive `as_of` gaps `< horizon_secs` (issue #436 B3 — equivalently `--step-days ≥ --horizon-days`), or the trajectory would double-count forward P&L and (with the B2 fix below) over-count an incumbent's proven periods.
- **Grid-level deflation** (LANDMINE-1) — the trial count is **pre-registered** before any scoring (§The bake-off driver), so the multiple-testing correction is honest. `deflated_sharpe` (Bailey & López de Prado 2014) deflates each config's Sharpe by the expected maximum under the nulls; `PBO` (CSCV probability of backtest overfitting), `romano_wolf` (StepM FWER), and `hansen_spa` (SPA) form the grid-level validator panel. **The scalar Deflated-Sharpe bar and the bootstrap Validators take trial counts kept *separate* by construction (issue #436 A2/A8), not forced equal:** `expected_max_sharpe` takes the **full pre-screen `N_GRID`** (every config the menu could have produced — the honest search multiplicity), whereas `PBO`/`romano_wolf`/`hansen_spa` are bootstraps over the matrix **columns** and structurally cannot reflect screened-out or unrun configs, so they take the run-set column count (incl. the benchmark). **#445 defect 4: with 8a no longer pruning, the run-set equals the full pre-screen grid, so the two counts now coincide in the current driver** (the `true_clv` preflight applies upstream of `N_GRID`, so `n_grid_full` already reflects any exclusion); the split is retained for a future horizon-consistent screen that drops configs. `PBO` additionally **refuses** (returns `NaN` + a `degenerate` flag) under near-zero cross-config dispersion, where the IS-best/OOS-rank machinery is meaningless — the old `<=`-rank tie rule silently returned `PBO=0` ("not overfit"); the gate now fails *safe* (issue #436 A7).
- **Is following viable at all?** — `brown_goetzmann_cpr` (contingency-table cross-product ratio) tests whether winners persist period-to-period; a no-persistence population is grounds for a NO-GO regardless of any single config's apparent edge. Wallets sitting at **exactly** a period's median are dropped before the 2×2 is tabulated (issue #436 C3): net-edge data has a zero mass-point (many wallets at exactly 0 = the median), and a bare `> median` would lump that whole block into the loser cell — inflating loser-loser and manufacturing a spurious persistence GO. The degenerate table now certifies a GO **only** for genuine perfect persistence (real winners *and* losers, zero reversals → `cpr = ∞`); an empty winner/loser class is no-signal and fails safe (`go = False`).
- **Cross-check vs live** — `paper_fills_crosscheck` compares the harness's leaderboard against realized live P&L from Supabase `paper_fills`, flagging any wallet the harness ranks well but that is bleeding live.
- **Winner's-curse uncertainty on the selected arm** — `akm_inference_on_winners` (Andrews-Kitagawa-McCloskey, median-unbiased conditional estimate + CI for the argmax), `mrsw_rank_cs` (Mogstad-Romano-Shaikh-Wilhelm top-τ rank confidence set; hand-rolled because the cited `csranks` package is not on PyPI), and `fcr_selected_ci` (Benjamini-Yekutieli false-coverage-rate-adjusted CIs for the selected set). The AKM conditioning needs a **strict** selection event: when the awarded arm is not strictly the max — below it, OR an **exact top tie** with the runner-up (#445 defect 7) — the truncated-normal law is ill-posed at its boundary, so it falls back to the honest **unconditional** normal CI rather than a spurious shrinkage (a tie-aware selection event is out of #445 scope).

## The bake-off driver

`scripts/ranker/bakeoff.py` composes the modules into a staged sweep:

1. **8a — estimator screen** (`screen_estimators`, **advisory-only since #445 defect 4**): score each estimator at each cutoff on a cheap point-in-time forward-copy-P&L proxy (no `pe-backtest`) and rank them. **Pruning is disabled** — the proxy target (final payoff over the forward window) does not match the realized + CLOB-MTM horizon objective the trajectories optimize (`_forward_copy_pnl` could prune an estimator the true objective would rank the winner), so **all registered estimators are carried into `N_GRID`** and the screen output is retained only as advisory diagnostics (a horizon-consistent screen is a deferred optimization, not this remediation's scope). The screen still runs on the **same gated universe the trajectories do** — the static `slice_by_criteria` plus the per-`as_of` recency/`ranker_min_trl` eligibility gate, under the canonical criteria `criteria[0]` (issue #436 A3/D1). The only estimator removed before `N_GRID` is the `true_clv` arm, dropped by the #445 defect-10 coverage preflight (§The shared substrate).
2. **8b — pre-register `N_GRID`** (`pre_register_grid`): with 8a no longer pruning (#445 defect 4), enumerate the full `estimator × deflator × policy × criteria × churn_cost` grid and emit a manifest `{created_at, n_grid, axes, grid_keys}`; `n_grid` therefore equals the full pre-screen trial count (it can still be smaller only via the upstream `true_clv` preflight exclusion). `n_grid` is the frozen run-set trial count (LANDMINE-1); a key collision (a duplicate axis level producing a duplicate config key) is asserted absent so two distinct configs can never silently merge into one matrix column (issue #436 A8). The baseline config key is asserted present.
3. **8c — trajectories** (`run_trajectories` → `run_trajectory`): each grid point runs the full walk-forward trajectory above. Per step: split, eligibility (recency + `ranker_min_trl`), uniqueness weights, estimator score, deflation gate, `policy.step`, then a real `pe-backtest` run via `SubprocessBacktestRunner` (shelling to the Rust injected-set path, §Data pipeline), wrapped in a per-run `MemoizingBacktestRunner`. **Churn cost** is `churn_cost ×` the **positive-part L1 weight movement** `Σ max(weightᵢ − prev_weightᵢ, 0)` — the capital newly deployed into a new-or-larger position, the only move that costs under hold-to-resolution (a weight decrease / eviction halts new copies but is not itself charged; issue #436 D3). For the three hard-set policies (weight 1.0) this reduces exactly to the count of newly-admitted wallets — unchanged semantics — while `policy_online_weighting` (continuous weights normalized to the same total mass as a hard top-k) additionally pays for a wallet *ramping its weight up*, which a bare admission count missed. The **memo** (issue #436 D2) keys the injected-set backtest on `(sorted followed set, flat_usd, MTM window)` — the backtest is a deterministic, order-independent pure function of the followed *set* and the forward-MTM window (issue #436 Phase E: the emitted `unrealized_pnl` flow depends on `(as_of, horizon)`, so the window joins the key; the churn deduction still happens in Python after) — so the two churn-cost levels (which never change the set or the window) and every repeated `(followed set, window)` within a run cost **one** backtest each; `run_bakeoff` reports the realized `distinct / total` count. `policy_hybrid_displacement`'s "proven incumbent" count is taken over live-P&L periods **closed by `as_of`** only (issue #436 B2), mirroring the demoter: the accumulating `live_pnl` carries future-period rows from prior steps' horizon windows, and counting them would let a future period mark an incumbent "proven" and shield it from displacement. The `empirical_bernstein` demoter is a **fixed-n** Maurer-Pontil upper-CB queried every step on a growing n, so its nominal `δ` is **not** a time-uniform ("anytime-valid") guarantee over the trajectory — the optional-stopping inflation is accepted (not relabeled, since no code/doc ever claimed anytime-validity) because demotion is AND-gated by cumulative realized P&L `< 0` and `min_periods` and a delayed demotion is low-cost; a stitched confidence sequence is the principled future fix and a live-policy change out of this phase's scope (issue #436 C4). The per-step deflation gate's `n_trials` is the **candidate count**, not `N_GRID`, and its Sharpe is **uniqueness-weighted** so the gate and the ranker agree on a wallet's edge (issue #436 A4). A period with **no eligible set / no surviving signal / an empty followed set** records `NaN` (the config held nothing — *excluded* from its moments), never `0.0` — so a dead config cannot earn a low-variance `0` that out-ranks a live one (issue #436 A9). **#445 defect 1 — "held nothing" also resets carry:** `prev` returns to an empty set and the policy is rebuilt via the `build_policy` seam (clearing `OnlineWeighting`'s online weights and, with an empty `prev`, the knockout/hybrid incumbency), so a later re-entry pays *full* churn rather than inheriting the pre-gap set; `live_pnl` (realized-only evidence) is preserved across the gap and no synthetic P&L is fabricated. `run_trajectory` also returns the **final-step followed set + per-wallet scores** captured during the run (issue #436 A1, below).
4. **Leaderboard + winner/NO-GO** (`grid_deflate` → `select_winner_or_nogo`): a verdict requires `≥ ranker_min_periods` walk-forward cutoffs — below that the CSCV/Romano-Wolf/Hansen-SPA/DSR bootstrap panel degenerates to a *silent* always-NO-GO, so the gate emits an **explicit** `insufficient periods` NO-GO and the operator raises `--steps` (issue #436 B4; the `main` default is `24`). **#445 defect 2 — the floor applies to the CLEANED dense matrix, not the raw row count:** the no-signal panel is cleaned *first* (all-`NaN` configs dropped; the remainder made rectangular by dropping periods any surviving config missed, so the bootstrap Validators get a dense matrix — A9), then `ranker_min_periods` is enforced on the clean row count — so a panel with enough *raw* rows that cleans down below the floor is still an explicit insufficient-periods NO-GO (the decision payload reports raw / clean / dropped period counts), never a leaderboard evaluation on a too-short dense matrix. A config is declared **WINNER** only if it is the highest-cumulative-return config that is **Romano-Wolf superior and beats `t_stat_baseline`** — *iterating* challengers by descending cum-return rather than testing only the cum-argmax, which may be an uncertified high-variance config (issue #436 A5) — **and** Hansen-SPA is significant at `ranker_fdr_q`, `PBO < ranker_pbo_max` (a degenerate `NaN` PBO fails *safe*, A7), and the `brown_goetzmann_cpr` premise holds. Otherwise it returns an explicit **NO-GO** with the failing-reason list. A winner whose *estimator* is the baseline is labeled a **policy/criteria-only win** (`baseline_estimator_win`, A11). The winner carries its AKM/MRSW/FCR uncertainty — **pointed at the awarded config** (which need not be the mean-argmax — A5), degrading to an unconditional CI when it is not the max — plus an **advisory** grid-DSR (`winner_grid_dsr`/`grid_dsr_advisory_low`, `ranker_grid_dsr_min`, A6; reported not gated, since the RW/SPA/PBO panel already deflates the leaderboard).

**The deliverable + cross-check (issue #436 A1).** The recommended wallet set is the **winning trajectory's frozen final-step followed set** — the set the winner actually rode, applying *that config's* criteria/eligibility/deflation/policy — captured during the run and threaded out via the `GridPoint` map (falling back to the baseline config on a NO-GO). It is **not** re-derived by a cold re-score of the winning estimator on the un-sliced in-sample at the latest `as_of`: three of the four policies are stateful (`KnockoutBackfill`/`HybridDisplacement` carry `prev`, `OnlineWeighting` carries an EWMA), so a cold re-application with empty state degenerates them into a memoryless top-k and would mis-represent the deliverable. **#445 defect 1:** if the *final* cutoff is no-signal the deliverable is **empty** — `run_trajectory` does not fall back to the most recent non-empty set, so the cross-check reflects the latest cutoff, not stale history. **The cross-check identity follows `final_follow` (#445 defect 5):** `main`'s `paper_fills` cross-check (`crosscheck_deliverable`) builds its frame from `final_follow.wallet` and *left-joins* score/rank metadata, so a stateful policy's held incumbent that is absent from the fresh `final_scores` still appears in the live-loser check (the pre-#445 `scores ∩ follow` intersection silently dropped it). It reports `overlap_count` / `overlap_fraction` vs `len(final_follow)`; a **successful** live fetch with a non-empty followed set but **zero overlap** is a hard verification failure (deliverable/live identity drift — wallet casing/source), not a clean zero-row result, while a missing-credentials fetch stays an advisory skip for local/dev runs.

## Data pipeline and backtest seam

The harness needs two pieces of Rust plumbing, both additive and idempotent on the cache, both deploying nothing live:

- **`pe-backtest` injected-set path (PR3).** `injected_wallets_path` makes the backtester follow an explicit wallet list (ranker bypassed) and emit `pnl_by_period.ndjson`. Each row is `{wallet, period_end, realized_pnl, unrealized_pnl, n_fills, notional, is_horizon_mtm, open_at_horizon, marked_at_horizon, positions_in_window, resolution_lags_secs}` (money fields serialized as JSON floats for the Python harness; never fed back into P&L math). There are two row kinds: **realized day rows** (`is_horizon_mtm=false`, one per `(wallet, UTC-day)`, `unrealized_pnl=0`) and — only when a forward-MTM window is configured (§Forward mark-to-market) — one **horizon MTM row** per wallet (`is_horizon_mtm=true`, the flow in `unrealized_pnl`, the coverage counts, and the issue #436 Phase F / F3a resolution diagnostics `positions_in_window` + `resolution_lags_secs`). The load is **bounded** — only the injected wallets' trades — so `max_trade_count = 0` is safe on the production cache without disabling any guard code. Without a window, `unrealized_pnl` stays the documented `0.0` sentinel. Injected mode requires `flat_usd` and is incompatible with `kelly_sweep_fractions`.
- **Forward mark-to-market (issue #436 Phase E).** Slow-resolving forward edge — a copied position opened in the forward window that has not resolved by the horizon — was zeroed (the dominant resolution-speed bias the audit found). With both `mtm_window_start_unix` (`as_of`) and `mtm_window_end_unix` (`horizon`) set on the injected path (the Python harness passes them per step), the binary loads a bounded `ClobMarkIndex` (`market_price_history ⋈ token_conditions`, `source='clob'`, for only the injected markets) and marks still-open positions. **#445 defect 3:** the MTM pass **realizes** (rather than marks) a still-open position whose market resolves inside `(bought, horizon]` — even when no later copied-wallet trade advanced the simulation's date axis past the resolution, so the per-day resolution sweep (which only fires on trade dates) never reached it and it would otherwise be mismarked at a stale CLOB mid instead of realized at its 0/1 outcome. Such a position emits a realized `period_pnl` row stamped on its **resolution day** and is excluded from horizon marking (`close_unix = resolved_at`); it stays *open-at-sim-end* for the simulation report (bankroll/Sharpe untouched, matching the open-at-sim-end policy — its resolution is past the last trade), but the bake-off forward-MTM output realizes it in-window. Only positions genuinely unresolved by the horizon reach the mark below. The mark is a **flow**, not a stock: per wallet, `unrealized_pnl = Σ_{open at horizon}(mark_H − cost) − Σ_{open at as_of}(mark_as_of − cost)`. The flow is what makes summing `realized + unrealized` over the window **telescope** to each position's true lifecycle P&L across the trajectory's adjacent windows — the literal `mark − cost` *stock* would mark a spanning position in window *k* AND count its realized close in window *k+1*, double-counting the cost on exactly the slow-resolvers MTM exists to value. `realized_pnl` is untouched, so the `live_pnl`/demoter path (which filters `~is_horizon_mtm` and assumes settled per-period P&L) stays realized-only. The mark uses the latest CLOB sample at-or-before the boundary (`arg_max(price, t ≤ boundary)`, matching the true-CLV close) with **no staleness cap** (operator decision) — look-ahead-safe because the horizon mark is inside the forward/OOS window and never feeds the in-sample decision. **Coverage-bounded (E3):** a position open at the horizon with no CLOB series contributes 0 and is counted `open_at_horizon` but not `marked_at_horizon`; `run_bakeoff` surfaces `marked / open` per `(config, period)` (`mtm_coverage.json`) so the resolution-speed residual — which thins at older `as_of`, since CLOB coverage is measured on recent markets — is reported beside the winner, not implicit. **Resolution-lag distribution (issue #436 Phase F / F3a):** coverage measures only CLOB-series *availability*, not how *slow* the unresolved edge is, so each MTM row also carries `positions_in_window` (open-at-horizon + the wallet's closed-in-window positions — the denominator for the open-at-horizon fraction `open / positions`) and `resolution_lags_secs` (per open-at-horizon position, `resolved_at − as_of`; `-1` = the market never resolved → *censored*). `mtm_coverage.json` then reports, per `(config, period)` and per config overall, the open-at-horizon fraction plus the lag distribution (`n`, `censored`, `censored_frac`, `p50/p90/max` in days). This is **advisory only** — it is built from post-horizon resolution times and never enters the objective or the verdict (which stay realized + MTM-flow). The fraction is conditioned on surviving MTM rows: a wallet whose entire window footprint is positions opened and closed strictly inside the window (no mark at either boundary) emits no MTM row, so those positions count toward neither numerator nor denominator.
- **CLV / Gamma pipeline (PR4).** A dedicated CLOB `GET /prices-history` client (`crates/source-polymarket-public/src/clob_prices_history.rs`, throttled by `clob_prices_history_min_interval_ms` on its own fetcher so it does not loosen the Data-API gate), a `market_price_history` table, a `start_date_unix` column backfilled from Gamma `createdAt`, the `pe-bootstrap prices-history` subcommand (pass 1 = `start_date_unix` on decided-outcome markets; pass 2 = the coarse pre-resolution series at `clob_prices_history_fidelity_minutes` over `prices_history_window_secs`), and an optional `market_price_history` parquet/DuckDB view. The proxy-CLV axis runs without the parquet; true-CLV consumes `market_price_history`. The batch `POST` variant and order-flow consumers are deferred to #418. Issue **#429 PR3** adds a `source` provenance column to `market_price_history` (`'clob'` is the only writer today — PR2's `scripts/ranker/clv_source_comparison.py` memo returned the `clob_only` verdict, dropping the planned trades-derived pass) plus a `price_series_coverage_report()` ledger logged after each backfill (warns under `prices_history_coverage_warn_pct`, default 60, calibrated to PR2's measured ~63.6% usable-series ceiling, where "usable" = ≥`prices_history_min_series_points` points). The series build is **write-once** (`INSERT OR IGNORE` on the `(market_id, token_id, t)` PK) and documented "run before `purge`, never after", so a later trade purge can never shift a captured series.

## Running the bake-off

The bake-off is an **operator compute step**, not part of any PR's CI (CI exercises the harness with a fake `BacktestRunner`). It runs where DuckDB and the local `data/wallet_cache.db` live — the cache box — because `main` shells out to the real `pe-backtest` over the full cache. Prerequisites: the Python deps in `scripts/requirements.txt` (`scipy`, `arch`, `statsmodels`) plus `duckdb`; the additive DDL (`market_price_history`, `start_date_unix`) applied to the cache; and, for the true-CLV axis, the `prices-history` backfill run. See `26-DATA-REFRESH-AND-REOPTIMIZATION-RUNBOOK.md` for the cache-refresh procedure.

**Component verification (run before trusting any winner).** `scripts/verify_bakeoff_components.py` is the executable Phase-0 gate: it cross-checks every estimator, the deflation, the whole honesty layer (PBO/CSCV, SPA, RomanoWolf, AKM, MRSW, FCR, Brown-Goetzmann CPR), the empirical-Bernstein demoter, `weighted_stats`, and `_churn` against an **independent** reference — `scipy` / `statsmodels` / a published closed-form / a Monte-Carlo ground-truth recovery — not the harness's own drift-guards. Unlike the bake-off run itself, it needs no cache or network, is seeded (bit-deterministic), runs in CI, and exits non-zero if any component disagrees with its external reference. A winner is not trusted (nor frozen via #417) until it is green. **#445 hardening:** the suite adds an **exact CSCV/PBO enumeration** (production `PBO` vs an independent brute-force over all `C(s, s/2)` splits on a tiny fixed matrix) and a **constrained-optimizer NPMLE** reference (production EM vs an SLSQP fit of the Kiefer-Wolfowitz mixing weights over the simplex — same marginal log-likelihood + posterior), and it **fails loud** when a pinned external reference is missing: `statsmodels` (which backs the EB DerSimonian-Laird `tau²` cross-check) is required, so a CI image that dropped it FAILS the gate rather than silently degrading to a closed-form-only run.

**Compute budget (issue #436 D2).** Every `(config, step)` that runs is one full injected-set `pe-backtest` over the cache, so before locking a grid the operator confirms wall-clock from two cheap measurements: time one `runner.run`, and read the realized **distinct backtest count** the memo reports (`backtest_calls.distinct` / `.total` in the result and the `compute:` line `main` prints — no separate stubbed pass needed). Wall-clock ≈ `distinct × per-run ÷ read-only-cache parallelism`. The naive `n_grid_full × steps` may not exceed `ranker_bakeoff_max_backtests` (`run_bakeoff` raises otherwise); narrow `--ttr-hours` / `--bands` / `--min-trl` to fit. The persistent cross-run cache is deliberately deferred (its key/version/eviction correctness is the harness-integrity risk this epic guards) — the in-run memo suffices unless iteration cost proves prohibitive.

The output is the §Deliverable: a grid-deflated leaderboard and a recommended winning config or NO-GO, both feeding #417.

## Scope and reasoned dead-ends

**Out of scope** (tracked elsewhere): position sizing (→ `SizingMode`/#398); maker/taker and order-flow-leads-price, which need on-chain `OrderFilled` and the order-flow consumer of `market_price_history` (→ #418); productionizing the winner (→ #417).

**Reasoned dead-ends — do not re-propose** (full rationale in issue #421): OCBA / indifference-zone (needs resampling — observational data); James-Stein linear shrinkage (dominated by `gu_koenker_npmle`); CORRAL / discounted-UCB / EXP3.S / universal-portfolios (no exploration trade-off — we copy every awake wallet); comomentum / factor-crowding (no co-moving residual panel); spoofing / counterparty-graph / Benford (need depth, counterparties, or deleted data); reverse-line-movement (data we lack); VPIN/PIN/Hawkes as a wallet ranker (market-level = wrong unit); adaptive-conformal as a selection fix (interval coverage, not FDR-over-top-k).

**Accepted v1 limitations (issue #436 Phase F).** These are known, measured, and surfaced beside the winner rather than silently absorbed; they do not block the operator run but bound how the winner feeds #417.

- **Universe survivorship (F1).** The bake-off universe is the **current** `wallet_cache.db` snapshot, sliced per-`as_of` by the recency / `ranker_min_trl` eligibility gates — it is **not** a point-in-time roster. Because #385 **hard-deletes** purged wallets (proven losers via the Rule-A t-stat floor + dead-weight), a historical `as_of` slice is missing every wallet purged after the snapshot, and a true point-in-time roster is **unreconstructable** (the rows are gone). The directional bias is therefore **optimistic**: the losing wallets a copy strategy would have followed-and-bled-on are absent, so realized in-sample edge is flattered. A precise count of purged-but-historically-present wallets is not cheaply available from the DuckDB positions view (the purge leaves no in-extract ledger), so `main` writes `survivorship.json` (current universe wallet/position counts + the directional-bias flag) as the cheap exposure proxy and prints a one-line caveat. Mitigation if the bias ever needs bounding: snapshot the roster *before* each purge (out of scope for v1).
- **Flat-USD entry has no per-fill taker fee (F3).** The injected backtest sizes every copy at a flat `flat_usd` with no order-book taker fee modeled per fill; the entry cost is instead approximated **once per admission** by the swept `ranker_churn_cost_usd` (D3 — a blended $25-entry taker-fee + slippage estimate). A position re-sized up across steps under `OnlineWeighting` is charged the positive-part L1 weight movement, not a per-contract fee. This understates cost for high-churn configs relative to a true per-fill book walk (deferred with the #398 `SizingMode` / live price-impact gate).
- **`paper_fills` cross-check is circular (F3).** `paper_fills_crosscheck` compares the harness leaderboard against the **live** cohort's realized P&L, but that cohort was itself selected by a *prior* ranker — so the cross-check can only ever flag wallets that were already deployed (a survivorship-and-selection circularity). It is a **sanity flag** (a winner the harness ranks well but that bled live is a red flag), never an independent validation, and it is surfaced as such in the run output.
- **Entry band and CLV reversal (F3).** The default `0.15–0.85` entry band (swept against `0.30–0.70`) is a coarse mid-price filter, not a per-market liquidity/skew model. And the proxy/true-CLV anchor can **reverse** for a market whose price drifts against the eventual outcome between entry and the CLV close — CLV is a noisy single-market edge signal that only de-noises in aggregate (tens of trades), so a per-wallet CLV score is trusted only at the cohort level, never as a single-position verdict.
